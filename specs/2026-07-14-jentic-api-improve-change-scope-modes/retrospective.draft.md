## Deviations from the spec

- `plan.md` Group 3 task 14 asserted `docs/architecture.md` line 141 "says six-file"; in current `main` that file uses a tree diagram with no numeric count, so only `.claude/CLAUDE.md` carried the "six-file" wording. Implemented against reality: bumped `.claude/CLAUDE.md` six→seven and added `oasdiff`/modes to the architecture tree diagram, which satisfies `validation.md` check 5's intent even though the literal "seven files" phrasing only lands in `.claude/CLAUDE.md`.
- `plan.md` task 17 said to add a `full`-mode cost note to `docs/improve-cost-benchmark.md`, but that file carries a "Generated by scripts/bench-improve.js — Do not edit manually" banner. Implemented by editing the generator's render template in `scripts/bench-improve.js` and regenerating the doc from an unmeasured data set, so `validation.md` check 4's file list (which named only the `.md`) is intentionally broader in practice — `scripts/bench-improve.js` also appears in the diff.
- `plan.md`/`validation.md` documented the `oasdiff` invocation as `oasdiff breaking BASE REV --format json -o FILE`, but `-o` is oasdiff's short form of `--fail-on` (values `ERR`/`WARN`), not an output-file flag; as written the command errors and never writes the file, and without `--fail-on` oasdiff exits 0 even on a detected break (masking real breaks). Corrected during pre-push review to `--format json --fail-on WARN > FILE`, with the exit-code contract fixed to `1 = break / 0 = none / 100+ = operational error`. Verified against the real `tufin/oasdiff` image.

## Root cause

[ONE_OR_TWO_SHORT_PARAGRAPHS — why the spec missed this. ## Lesson for future specs

[LESSON_1 — actionable guidance. Candidate: when a spec introduces a new external CLI tool, the plan should require verifying the tool's actual flag/exit-code contract (run `--help` or a smoke invocation) before documenting invocations, rather than transcribing from the tool's README/roadmap.]
